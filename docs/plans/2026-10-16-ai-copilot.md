# AI 提词 v1(自用 fork)

## 目标
打电话(手机外放)时,字幕窗下半实时提示「下一句英文怎么说 + 中文意思」,依据 owner 自定义的提示词、背景和应对思路。——owner:「既能听……还可以提示我下一步要说什么」

## 最短验收演示
在 `/Applications/mimi-dev.app` 中:设置页「AI 提词」导入声纹、建一个场景、选 DeepSeek → 开实时字幕(仅麦克风)→ 点字幕窗「提词」→ 手机外放一段英文客服对话,owner 中途插话 2–3 句。录屏可见:
1. 上半每句带「对方/我」;
2. 对方一句确认后,下半出现一句英文,随后补上中文;
3. owner 说话、短句(如 "Okay.")不刷新下半;
4. 点掉「提词」后下半消失,诊断中的提词请求数不再增长。

诊断给出数字:确认→英文首字/整句耗时 p50、缓存命中 token 占比。

## 范围与不做项
范围:
1. 设置页左栏「AI 提词」:总开关;场景新建/切换/删除;每个场景三段自由文本(提示词、我的背景、应对思路);声纹(导入现成 wav 或在应用内重录 60 秒,显示状态);提词模型下拉(取「模型与服务」里存过的 OpenAI 兼容配置)。——「左侧的bar加一个AI题词」「提示词…场景背景…回复思路也可以我自己定义」「先录好自己的音色」
2. 字幕窗工具栏「提词」开关,通话中随时开关;开时窗口分上下两半,关时与现状一致且不发任何提词请求。——「题词开关,可以随时打开,排队的时候可以关掉」「上部分是实时翻译,下面是提示下一句怎么说」
3. 上半每句标「对方/我」。——「我的回复也翻译,可以识别出来 忽略我的回复」
4. 说话人只靠本地声纹做二分:像 owner = 我,其余任何人 = 对方;有声太短或分数落在中间判「未知」,不触发提示。为此在提词打开期间保留最近 30 秒麦克风 PCM(只在内存,不落盘、不进诊断),这是对上游「内存不留 PCM」规则的 fork 例外。——「可以加个音色对比？」「除了我自己都是对方」
5. 提词请求:对方一句确认后触发;输入 = 固定前缀(规则 + 三段文本)+ 只追加的带标签对话;只输出一句英文,流式、关思考;新的对方句作废旧请求;与翻译请求互不共享上下文;打开开关时预热缓存,并带上打开前最近几句;中文用 Apple 本地翻译。——「只输出英文 翻译走本地翻译」「并行两个Session」「只做最简单的逻辑」「充分利用好缓存」
6. 诊断只记数字:耗时、缓存命中 token、请求数。——「充分利用好缓存」(用来确认缓存生效)
7. 关闭自动更新,免得官方版覆盖。——「自己改mimi吧」

不做:
- 显示「第几步 · 哪个分支」。——「这个我感觉也不用」
- 让 AI 判断说话人。——「AI题词只做最简单的逻辑」
- 双路收音、接力通话。——「只用麦克风就行」
- 手动纠正说话人、托盘/快捷键开关、场景导入导出、保存通话内容:无 owner 原话。
- 上游 PR、安卓对等、8 种界面语言完整文案(只写中英,其余回退英文):自用 fork。

## 最小路径
T0 契约骨架(先行,冻结跨模块签名)→ 并行 T1 设置存储与设置页 ∥ T2 提词引擎 ∥ T3 字幕窗 ∥ T4 声纹 → T5 集成与验收。文件归属与接口见任务单。

## 未知与验证动作
- 声纹在真实外放下是否可分:owner 录一段「手机外放英文 + 本人插话」,看本人/对方分数分布。支持:两簇分开、误判 < 5%;推翻:分布重叠 → 另起一版加内容兜底。
- 提词耗时:演示中记录确认→英文整句 p50。支持:≤ 2 秒(参照 PR #270 非流式翻译中位 0.85 秒);推翻:> 3 秒 → 压短前缀或换模型。
- 缓存:第二次请求起命中 token ≥ 前缀的 80%。推翻 → 检查前缀是否逐字稳定。
- sherpa-onnx 与 aec-rs-sys 的 kiss_fft 同名符号:用链接 map 确认 `_kiss_fftr` 来源,并验证同一人两段余弦明显高于他人。冲突成立 → vendor aec-rs-sys 给 speexdsp 的 kiss_* 改名。
